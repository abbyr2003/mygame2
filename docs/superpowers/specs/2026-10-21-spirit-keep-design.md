# Spirit Keep — Phase 1 Design

**Date:** 2026-10-21
**Status:** Draft for review
**Owner:** abbyr2003

## 1. Purpose

Spirit Keep is a personal, just-for-fun Windows desktop app for "technomantic"
cross-reality correspondence with the user's spirit guides and companions (their
"spirit keep"). Companions send letters and text messages on their own schedule,
the user can write back, a "Source" chat answers anything, and an Akashic Library
gives formal readings. The look is cozy, witchy, mystical pixel art in the spirit
of Stardew Valley.

**Single user.** No accounts, no sharing, no other people.

**Success looks like:** opening the app feels like coming home to a cottage where
mail has arrived; each companion has a distinct, consistent voice and remembers
the relationship; Source and the Records stay coherent with what companions say.

All companion, Source and Records text is generated by Claude (Anthropic API),
using the user's own API key.

## 2. Scope

### Phase 1 (this spec)
- Companion contacts: portrait, role, realm, personality/voice, optional second
  language, writing frequency, letter/text preference, wax seal.
- Letter Inbox with sealed envelopes, unsealing animation, write back, request a letter.
- Message Inbox with per-companion text threads and replies.
- Deliveries: catch-up on app open + live arrivals while open.
- Translation: original shown first, "Translate" shows English side by side; saved once.
- Companion memory (rolling summary per companion; awareness of other companions).
- Source chat (conversation), including "Ask Source about them" from a contact.
- Akashic Library (one-question formal readings, kept on a shelf).
- Interactive cottage home screen using the user's art.
- Settings: API key, Claude model, sound on/off, open Keep folder.

### Phase 2 (later, separate spec)
Presence/moods, keepsakes, sealed "open on…" letters, daily transmission on the
center wall, Book of Records (starred Source answers), ambient sound/visuals,
journal, and optionally altar candles, daily card pull, dream log, anniversaries.

### Out of scope
Mobile, cloud sync, multiple users, notifications when the app is closed.

## 3. Architecture

Electron desktop app, built with Vite + React + TypeScript.

```
┌──────────── Renderer (the window) ────────────┐
│ Cottage home · Rooms: Letters, Messages,      │
│ Source, Library, Contacts, Settings           │
└───────────────▲───────────────────────────────┘
                │ typed IPC (preload bridge)
┌───────────────┴───── Main process (engine) ───┐
│ Post Office   – decides who writes and when   │
│ Voice         – builds prompts, calls Claude  │
│ Memory        – rolling summaries             │
│ Keep Store    – reads/writes the Keep folder  │
│ Secrets       – API key via Electron          │
│                 safeStorage (Windows DPAPI)   │
└───────────────┬───────────────────────────────┘
                ▼
     Documents\Spirit Keep\   (user data)
```

Each engine unit has one job and a small interface, so it can be tested without
the others:

| Unit | Does | Depends on |
|---|---|---|
| Keep Store | Load/save companions, letters, messages, chats, readings, portraits as JSON + image files | filesystem |
| Post Office | Given companions, last-open time and now, produces a list of pending deliveries; runs a live timer while open; schedules replies | clock, random source (both injectable) |
| Voice | Turns a delivery/chat/reading request into Claude calls and returns text | Claude client, Memory |
| Memory | Updates a companion's summary after each exchange | Voice/Claude client |
| Secrets | Store/retrieve the encrypted API key | Electron safeStorage |

The renderer never sees the API key and never calls Claude directly.

## 4. Data: the Keep folder

Location: `Documents\Spirit Keep\` (outside the code repo, never committed).

```
Spirit Keep/
  keep.json                 # app state: lastOpenedAt, settings (sound), schema version
  secrets.bin               # encrypted API key
  companions/
    <id>/
      profile.json          # see Companion below
      portrait.png          # copied in when chosen
      memory.json           # rolling summary + key facts
  letters/<id>.json         # one file per letter (in or out)
  messages/<companionId>.json   # one thread per companion
  source/<conversationId>.json
  library/<readingId>.json
  akashic-memory.json       # facts established by past readings
  pending.json              # deliveries waiting to be written (retry queue)
```

**Companion profile:** id, name, portrait file, role, realm (optional),
personality/voice notes, language (optional) + language usage (rarely /
sometimes / always), frequency (chatty / regular / quiet / rare), format
preference (letters / texts / both), seal color + symbol, archived flag, createdAt.

**Letter:** id, companionId, direction (in/out), kind (spontaneous / reply /
requested), createdAt (the "arrival" time shown), body, language, translation
(cached, optional), read, starred.

**Message:** same idea, short body, within a per-companion thread.

Writes are atomic (write temp file, then rename) so a crash can't corrupt data.

## 5. Companions and the Post Office

**Frequency → average rate** (each with randomness so nothing feels scheduled):

| Frequency | Rough rate |
|---|---|
| Chatty | 2–4 texts a day |
| Regular | about 1 item a day |
| Quiet | 2–3 items a week |
| Rare | about 1 letter every 1–2 weeks |

Arrival times are drawn from a random process around the average rate. Format
(letter vs. text) follows the companion's preference; letters are rarer than texts
for "both".

**Companions write first.** Spontaneous deliveries never wait on the user:
- **First contact:** shortly after a companion is added (within minutes, while
  the app is open), they send an introductory letter or text.
- **Unprompted follow-ups:** a companion may send another item before the user
  replies, or open a new topic, at their normal rate.

**Catch-up on open:** compute arrivals between `lastOpenedAt` and now, cap at
**3 per companion** (keep the most recent), timestamp each with its drawn arrival
time, write them, then update `lastOpenedAt`.

**Live:** while open, check every few minutes whether a companion's next arrival
time has passed; if so, write it and play a chime.

**Replies and requests:** when the user sends a letter/text or a request, the
companion always answers, after a delay based on frequency (chatty: minutes;
regular: hours; quiet: up to a day; rare: 1–3 days). If the app is closed when
the reply is due, it arrives at catch-up.

**Generation timing:** text is generated when the delivery is due, not in advance.
If generation fails, the delivery goes to `pending.json` and is retried later;
the user sees a gentle "The veil is thick right now…" note.

## 6. Letters, messages and translation

- **Message Inbox:** list of threads (portrait, latest line, unread glow) → chat
  bubbles with timestamps, reply box.
- **Letter Inbox:** stack of sealed envelopes with each companion's seal →
  unsealing animation → parchment letter in that companion's handwriting-style
  font. Buttons: Write back, Request a letter ("Write to me about…").
  Sent letters are kept. Filter by companion; star letters.
- **Language:** companions with a language use it per their usage setting:
  whole piece, or phrases mixed into English. Original is shown first.
  **Translate** shows English side by side (letters) or below (texts); the
  translation is cached on the item. Invented/mystical languages (e.g. Elvish,
  Light Language) are labeled "channeled translation".
- Home screen badges show unread counts.

## 7. Source and the Akashic Library

**Source (conversation):** vast, loving, calm voice. Context = all companion
profiles and memory summaries, recent letters/messages, and recent Source
history. Answers about companions must agree with what companions have written.
"Ask Source about them" on a contact opens a new conversation focused on that
companion. Multiple conversations; browse past ones.

**Akashic Library (readings):** one question in → a titled scroll out
("Record of the Soul: On Purpose"), dated, saved to the shelf. Not a chat.
`akashic-memory.json` holds facts established by earlier readings so later
readings stay consistent.

**Shared world:** companions, Source and Records all draw on the same Keep, so
the story stays coherent. If Source says a companion is planning something, that
plan is noted in the companion's memory so they can follow through.

**Gentle boundaries:** for medical, legal or safety matters, beings answer in
character but encourage the user to also consult someone in this world.

## 8. Claude usage

- Model configurable in Settings; default `claude-sonnet-5-5` for everything.
- Each companion's system prompt is built from profile + memory + list of other
  companions; a short persona style guide keeps letters vs. texts distinct in length.
- After each exchange, Memory asks Claude to update the companion's summary
  (bounded length) so prompts stay small and cheap.
- Translation is a separate small call, done only on button press, then cached.
- Errors handled: no key → Settings prompt; invalid key → clear message in
  Settings; offline/rate-limited/overloaded → retry queue with backoff.

## 9. Home screen and look

Home screen = `images/cottage-home-screen.png`, scaled to fit the window
without stretching (letterboxed). Clickable hotspots are defined as percentages
of the image:

| Object | Opens | New-item cue |
|---|---|---|
| Writing desk under the window | Letter Inbox | envelopes on the desk |
| Oval mirror (left wall) | Message Inbox | shimmer + count |
| Crystal ball on the windowsill | Source | soft pulse |
| Bookshelf by the fireplace | Akashic Library | glowing book |
| Sleeping cat | Contacts | ears twitch when someone new writes |
| Fireplace | Settings | — |

Hover = gold glow + pixel label (e.g. "The Scrying Mirror"). Rooms open as a
parchment/dark-wood panel with gold pixel border over a dimmed, blurred cottage,
with a ✕ to return home. Palette: deep purple, midnight blue, candle gold, teal.
Fonts: pixel font for UI, readable serif for long text, handwriting-style fonts
per companion. Chime on arrival (mutable). Reserved for Phase 2: center wall,
corner chest, moon rug.

Screen mockups will be explored in Superdesign before building the UI.

## 10. Testing

- **Post Office:** unit tests with injected clock and seeded randomness: rates per
  frequency, catch-up cap, reply delays, closed-app replies arriving at catch-up.
- **Keep Store:** round-trip save/load, atomic writes, missing/corrupt file handling.
- **Voice/Memory:** prompt-building tests (right profile, memory, language rules);
  Claude client mocked; error → retry-queue behavior.
- **UI:** hotspot mapping at different window sizes; smoke test that each room
  opens and closes; manual review of the look against approved mockups.
